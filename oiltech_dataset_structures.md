# Структуры датасетов для технологических данных нефтедобычи

Документ описывает рекомендуемые структуры датасетов для хранения технологических данных, поступающих от счётчиков, датчиков и систем управления оборудованием. Модель ориентирована на промышленную предметную область: КНС, кусты, скважины, насосы, трубопроводы, приборы учёта и расчётные интервалы работы оборудования.

## meter_readings_raw

Универсальный датасет показаний счётчиков. Используется для электроэнергии, воды, газа, нефти, тепла, реагентов и других ресурсов, которые измеряются приборами учёта.

| Поле | Тип | Что означает | Откуда берётся |
|---|---|---|---|
| `event_id` | `string` | Уникальный идентификатор события для защиты от дублей при повторной доставке сообщений | Генерируется источником данных или collector-сервисом |
| `source_system` | `string` | Система-источник данных | SCADA, АСКУЭ, поставщик воды, OPC-шлюз, MQTT gateway |
| `source_tag` | `string` | Исходный тег из внешней системы | Приходит из телеметрии, SCADA, OPC или файла поставщика |
| `meter_id` | `string` | Идентификатор прибора учёта | Берётся из справочника приборов учёта или извлекается из тега |
| `facility_id` | `string` | Производственный объект: КНС, куст, установка, площадка | Берётся из тега, паспорта оборудования или справочника объектов |
| `equipment_id` | `string` | Конкретное оборудование: насос, линия, скважина, агрегат | Берётся из тега или справочника оборудования |
| `equipment_type` | `string` | Тип оборудования, к которому относится счётчик | Например: `pump`, `well`, `pipeline`, `facility` |
| `resource_type` | `string` | Тип измеряемого ресурса | Например: `electricity`, `water`, `oil`, `gas`, `reagent` |
| `measurement_kind` | `string` | Тип показания | Например: `counter`, `period_volume`, `instant_value` |
| `moment` | `datetime` | Момент измерения для точечного или накопительного показания | Время измерения на стороне источника |
| `period_start` | `datetime` | Начало периода, если источник передаёт значение за период | Формируется источником или адаптером данных |
| `period_end` | `datetime` | Конец периода, если источник передаёт значение за период | Формируется источником или адаптером данных |
| `value` | `decimal` | Значение показания | Само измеренное или переданное значение |
| `unit` | `string` | Единица измерения | Например: `kWh`, `m3`, `m3/h`, `bar`, `C` |
| `quality` | `string` | Качество данных | Например: `good`, `bad`, `estimated`, `missing` |
| `status` | `string` | Состояние измерения или признак особенности показания | Например: `normal`, `overflow`, `reset`, `manual` |
| `received_at` | `datetime` | Время приёма сообщения системой | Заполняется collector-сервисом при записи в БД |

### Назначение

Этот датасет нужен для унификации разных форматов поставщиков. Например, один источник может передавать накопительные показания электросчётчика, другой - уже рассчитанное потребление за период. Внутри системы оба варианта приводятся к общей структуре через поля `measurement_kind`, `moment`, `period_start` и `period_end`.

## process_measurements_raw

Датасет мгновенных технологических параметров. Используется для давления, температуры, расхода, вибрации, тока, напряжения и других параметров, которые снимаются датчиками или передаются из SCADA/АСУ ТП.

| Поле | Тип | Что означает | Откуда берётся |
|---|---|---|---|
| `event_id` | `string` | Уникальный идентификатор события | Генерируется источником данных или collector-сервисом |
| `source_system` | `string` | Система-источник данных | SCADA, MQTT gateway, OPC UA gateway, промышленный контроллер |
| `source_tag` | `string` | Исходный технологический тег | Приходит из SCADA, OPC, MQTT или другой телеметрической системы |
| `sensor_id` | `string` | Идентификатор датчика | Берётся из паспорта датчика, справочника или извлекается из тега |
| `facility_id` | `string` | Производственный объект: КНС, куст, ДНС, установка | Берётся из структуры объекта, тега или справочника |
| `well_id` | `string` | Скважина, если параметр относится к скважине | Берётся из справочника скважин или из структуры тега |
| `equipment_id` | `string` | Оборудование: насос, трубопровод, ёмкость, задвижка | Берётся из тега или справочника оборудования |
| `equipment_type` | `string` | Тип оборудования | Например: `pump`, `well`, `tank`, `pipeline` |
| `parameter_id` | `string` | Измеряемый параметр | Например: `pressure`, `temperature`, `flow_rate`, `vibration`, `current` |
| `moment` | `datetime` | Момент измерения | Время датчика или SCADA |
| `value` | `decimal` | Значение технологического параметра | Приходит из сообщения датчика |
| `unit` | `string` | Единица измерения | Например: `bar`, `C`, `m3_h`, `mm_s`, `A` |
| `quality` | `string` | Качество значения | Формируется диагностикой датчика, SCADA или адаптером |
| `status` | `string` | Статус параметра или датчика | Например: `normal`, `warning`, `alarm`, `offline` |
| `received_at` | `datetime` | Время приёма сообщения системой | Заполняется collector-сервисом |

### Назначение

Этот датасет хранит временные ряды технологических параметров. Он подходит для последующих алгоритмов агрегации, контроля порогов, расчёта средних значений, поиска выбросов и формирования аварийных событий.

## equipment_states_raw

Датасет состояний оборудования. Используется для фиксации факта работы, остановки, аварии, ремонта или изменения режима управления насосами, задвижками, компрессорами и другим оборудованием.

| Поле | Тип | Что означает | Откуда берётся |
|---|---|---|---|
| `event_id` | `string` | Уникальный идентификатор события | Генерируется источником данных или collector-сервисом |
| `source_system` | `string` | Система-источник данных | SCADA, АСУ ТП, контроллер оборудования |
| `facility_id` | `string` | Производственный объект | КНС, куст, установка, площадка |
| `equipment_id` | `string` | Оборудование | Насос, задвижка, компрессор, агрегат |
| `equipment_type` | `string` | Тип оборудования | Например: `pump`, `valve`, `compressor` |
| `state` | `string` | Физическое состояние оборудования | Например: `running`, `stopped`, `fault`, `maintenance` |
| `mode` | `string` | Режим управления оборудованием | Например: `auto`, `manual`, `remote`, `local` |
| `scheme_id` | `string` | Технологическая схема или режим работы объекта | Приходит из системы управления или определяется по состоянию объекта |
| `moment` | `datetime` | Момент фиксации состояния | Время источника данных |
| `quality` | `string` | Качество сигнала состояния | Формируется SCADA, диагностикой или адаптером |
| `received_at` | `datetime` | Время приёма сообщения системой | Заполняется collector-сервисом |

### Назначение

Этот датасет нужен для восстановления временной шкалы работы оборудования. На его основе можно рассчитывать интервалы работы насосов, простои, аварийные периоды и проверять противоречия, например ситуацию, когда насос находится в состоянии `stopped`, но по нему есть потребление электроэнергии.

## equipment_work_periods

Расчётный датасет интервалов работы оборудования. Он не приходит напрямую с датчиков, а формируется алгоритмом на основе `equipment_states_raw`.

| Поле | Тип | Что означает |
|---|---|---|
| `facility_id` | `string` | Производственный объект, к которому относится оборудование |
| `equipment_id` | `string` | Насос, агрегат или другое оборудование |
| `equipment_type` | `string` | Тип оборудования |
| `period_start` | `datetime` | Начало интервала состояния |
| `period_end` | `datetime` | Конец интервала состояния |
| `state` | `string` | Состояние оборудования в течение интервала |
| `duration_seconds` | `int` | Длительность интервала в секундах |
| `quality` | `string` | Качество рассчитанного интервала |

### Назначение

Этот датасет используется для расчёта наработки оборудования, простоев, аварийных интервалов и производственных KPI. Например, по нему можно посчитать, сколько часов насос был в работе за сутки, сколько времени находился в аварии и как это связано с расходом, давлением или потреблением электроэнергии.

## Рекомендуемые преобразования

### `meter_readings_raw -> period_consumption`

Алгоритм рассчитывает потребление за период из накопительных показаний счётчиков. Для каждой пары соседних показаний одного `meter_id` считается разница между конечным и начальным значением.

### `process_measurements_raw -> indicators`

Алгоритм агрегирует мгновенные технологические параметры по временным окнам. Например, рассчитывает среднее давление, максимальную вибрацию или средний расход за час.

### `equipment_states_raw -> equipment_work_periods`

Алгоритм восстанавливает интервалы работы оборудования. Он сортирует события состояния по `equipment_id` и `moment`, после чего строит интервалы между соседними событиями.
