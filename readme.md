# Описание программного продукта OilTech

## Аннотация

OilTech — учебно-практический программный продукт для хранения, приёма, обработки и отображения технологических данных нефтедобывающего предприятия. Система принимает телеметрию по MQTT, сохраняет данные в PostgreSQL, позволяет создавать динамические датасеты, описывать преобразования между ними и выполнять алгоритм расчёта периодов работы оборудования.

## Техническое задание

### Введение

Наименование программного продукта: OilTech.

Область применения: автоматизация хранения, приёма, обработки и визуализации технологических данных нефтедобывающего предприятия.

Объект автоматизации: технологические данные, поступающие от датчиков, счётчиков, систем управления оборудованием и симуляторов источников данных.

Программный продукт предназначен для демонстрации базовой архитектуры информационной системы технологических показателей предприятия. В текущей версии система реализована как MVP и запускается локально через Docker Compose.

### Основания для разработки

Основанием для разработки является учебно-практическая постановка задачи по созданию информационной системы хранения, обработки и преобразования технологических показателей нефтедобывающего предприятия.

Тема разработки: информационная система приёма, хранения и преобразования технологических данных нефтедобывающего предприятия.

### Назначение разработки

Функциональное назначение программы:

- создание датасетов технологических данных;
- автоматическое создание физических таблиц PostgreSQL под датасеты;
- приём MQTT-сообщений;
- сохранение входящей телеметрии в PostgreSQL;
- регистрация алгоритмов обработки данных;
- создание трансформаций между датасетами;
- ручной и автоматический запуск трансформаций;
- расчёт периодов работы оборудования по событиям состояний;
- отображение данных в web-dashboard.

Эксплуатационное назначение программы:

- локальный запуск в Docker Compose;
- демонстрация архитектуры технологической информационной системы;
- использование в качестве основы для дальнейшего расширения проекта.

### Требования к функциональным характеристикам

Программа должна обеспечивать следующие функции:

- создание датасета с указанием кода, наименования, MQTT-топика и колонок;
- хранение метаданных датасетов;
- создание физической таблицы для каждого датасета;
- получение списка датасетов;
- получение схемы конкретного датасета;
- получение строк датасета;
- приём сообщений из MQTT;
- запись полезной нагрузки MQTT-сообщения в таблицу соответствующего датасета;
- создание алгоритма с указанием URL запуска;
- создание трансформации между исходным и целевым датасетом;
- запуск трансформации вручную;
- запуск трансформации по расписанию через scheduler-service;
- хранение истории запусков трансформаций;
- выполнение алгоритма `equipment_states_raw -> equipment_work_periods`;
- отображение данных в web-dashboard.

### Требования к данным

В системе заведены следующие основные датасеты:

#### meter_readings_raw

Датасет показаний счётчиков. Используется для хранения показаний приборов учёта ресурсов.

Поля:

- `event_id`;
- `source_system`;
- `source_tag`;
- `meter_id`;
- `facility_id`;
- `equipment_id`;
- `equipment_type`;
- `resource_type`;
- `measurement_kind`;
- `moment`;
- `period_start`;
- `period_end`;
- `value`;
- `unit`;
- `quality`;
- `status`.

#### process_measurements_raw

Датасет мгновенных технологических параметров. Используется для хранения показаний датчиков давления, температуры, расхода, вибрации, тока и оборотов.

Поля:

- `event_id`;
- `source_system`;
- `source_tag`;
- `sensor_id`;
- `facility_id`;
- `well_id`;
- `equipment_id`;
- `equipment_type`;
- `parameter_id`;
- `moment`;
- `value`;
- `unit`;
- `quality`;
- `status`.

#### equipment_states_raw

Датасет событий состояния оборудования. Используется для хранения фактов запуска, остановки, аварии и обслуживания оборудования.

Поля:

- `event_id`;
- `source_system`;
- `facility_id`;
- `equipment_id`;
- `equipment_type`;
- `state`;
- `mode`;
- `scheme_id`;
- `moment`;
- `quality`.

#### equipment_work_periods

Расчётный датасет периодов работы оборудования. Формируется алгоритмом на основе `equipment_states_raw`.

Поля:

- `facility_id`;
- `equipment_id`;
- `equipment_type`;
- `period_start`;
- `period_end`;
- `state`;
- `duration_seconds`;
- `quality`.

### Требования к надёжности

В текущей версии предусмотрены следующие меры:

- PostgreSQL используется как основное хранилище данных;
- для MQTT применяется отдельный broker;
- повторные сообщения могут отфильтровываться по `event_id`, если это поддержано схемой таблицы и логикой записи;
- история запусков трансформаций сохраняется в системных таблицах;
- scheduler-service запускает трансформации периодически;
- алгоритм фиксирует результат запуска через core-service.

Ограничения текущей версии:

- нет полноценной модели авторизации;
- нет промышленной обработки отказов MQTT broker;
- нет распределённой блокировки запуска алгоритмов;
- нет TimescaleDB и политик хранения временных рядов;
- нет production-ready observability.

### Функциональное назначение

Программа предназначена для:

- приёма технологических данных по MQTT;
- хранения данных в PostgreSQL;
- управления структурами датасетов;
- выполнения преобразований данных;
- расчёта периодов работы оборудования;
- отображения данных через web-dashboard.

Программа решает следующие классы задач:

- сбор телеметрии;
- хранение временных рядов;
- преобразование событий в интервалы;
- получение данных через REST API;
- визуализация технологических данных.

### Описание логической структуры

Программа состоит из следующих частей:

#### core-service

Главный HTTP-сервис. Предоставляет REST API для управления датасетами, алгоритмами, трансформациями и данными.

Основные функции:

- создание датасетов;
- получение датасетов;
- получение строк датасета;
- создание алгоритмов;
- создание трансформаций;
- запуск трансформаций;
- получение истории запусков;
- получение дерева трансформаций.

#### collector-service

Сервис приёма MQTT-сообщений.

Основные функции:

- подключение к MQTT broker;
- подписка на топики датасетов;
- разбор входящих сообщений;
- запись payload в PostgreSQL.

#### mqtt-simulator

Симулятор источников технологических данных.

Основные функции:

- публикация показаний счётчиков в `meter_readings_raw`;
- публикация технологических измерений в `process_measurements_raw`;
- публикация состояний оборудования в `equipment_states_raw`.

#### scheduler-service

Сервис автоматического запуска трансформаций.

Основные функции:

- периодический просмотр включённых трансформаций;
- проверка времени последнего запуска;
- запуск трансформаций по расписанию.

#### equipment-work-periods

Сервис алгоритма расчёта периодов работы оборудования.

Основные функции:

- получение команды запуска;
- чтение данных из `equipment_states_raw`;
- сортировка событий по оборудованию и времени;
- построение интервалов между соседними событиями;
- запись результата в `equipment_work_periods`.

#### web-dashboard

Статический web-интерфейс.

Основные функции:

- отображение количества датасетов;
- отображение количества трансформаций;
- отображение количества технологических измерений;
- отображение количества рассчитанных периодов работы;
- отображение текущих состояний оборудования;
- отображение последних технологических параметров;
- отображение последних периодов работы оборудования.

### Алгоритм преобразования equipment_states_raw -> equipment_work_periods

Алгоритм выполняет следующие действия:

1. Получает запрос на запуск.
2. Определяет трансформацию по `transformation_code`.
3. Читает строки из `equipment_states_raw`.
4. Группирует события по `facility_id` и `equipment_id`.
5. Сортирует события внутри каждой группы по `moment`.
6. Для каждой пары соседних событий строит интервал:
   - `period_start` равен времени первого события;
   - `period_end` равен времени следующего события;
   - `state` равен состоянию первого события;
   - `duration_seconds` равен разнице между `period_end` и `period_start`.
7. Записывает результат в `equipment_work_periods`.

Пример:

```text
14:00 PUMP-01 running
14:15 PUMP-01 stopped
14:40 PUMP-01 running
```

Результат:

```text
14:00 - 14:15 running
14:15 - 14:40 stopped
```

### Используемые технические средства

При работе программы используются:

- персональный компьютер или сервер с Docker;
- PostgreSQL как реляционная база данных;
- Mosquitto как MQTT broker;
- web-браузер для dashboard;
- Docker Compose для локального запуска.

### Входные данные

Входными данными являются:

- HTTP-запросы к core-service;
- MQTT-сообщения от simulator;
- записи в PostgreSQL;
- команда запуска алгоритма.

MQTT-сообщение содержит:

- `event_id`;
- `source_timestamp`;
- `payload`.

Пример payload для `equipment_states_raw`:

```json
{
  "event_id": "state-FAC-001-PUMP-01-001",
  "source_system": "SCADA",
  "facility_id": "FAC-001",
  "equipment_id": "PUMP-01",
  "equipment_type": "pump",
  "state": "running",
  "mode": "auto",
  "scheme_id": "SCH-01",
  "moment": "2026-05-20T10:00:00Z",
  "quality": "good"
}
```

### Выходные данные

Выходными данными являются:

- JSON-ответы REST API;
- записи в таблицах PostgreSQL;
- рассчитанные строки в `equipment_work_periods`;
- визуальные блоки web-dashboard.

Пример результата алгоритма:

```json
{
  "facility_id": "FAC-001",
  "equipment_id": "PUMP-01",
  "equipment_type": "pump",
  "period_start": "2026-05-20T10:00:00Z",
  "period_end": "2026-05-20T10:15:00Z",
  "state": "running",
  "duration_seconds": 900,
  "quality": "good"
}
```

## Заключение

OilTech демонстрирует базовый цикл работы промышленной информационной системы технологических данных:

```text
MQTT simulator -> MQTT broker -> collector-service -> PostgreSQL -> algorithm -> calculated dataset -> dashboard
```

Система может использоваться как основа для дальнейшего развития: добавления новых датасетов, новых алгоритмов, фильтрации, авторизации, мониторинга и промышленной эксплуатации.
